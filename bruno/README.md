# Bruno collection

A [Bruno](https://www.usebruno.com) collection for the whole API: every REST operation of the four OpenAPI contracts, the
GraphQL examples, and a login as the user you pick. Bruno keeps requests as plain text files, so the collection lives in git,
shows up in pull requests and needs no account (Postman does not give you that).

Open it: Bruno → *Open Collection* → this folder. Pick an **environment** (top right): that is the user you act as.

## Environments = users

`alice` (user), `mod` (moderator), `admin` (administrator) and, after `make seed`, `bob carol dave erin frank grace heidi judy`.
Password `password` for all of them. Each environment carries the ids that fit that user from the seed data (their own wallpaper,
collection, unread notification, image), so the requests work without copying ids around. Switching the environment switches the
user: the token is fetched by OAuth2 password grant from Keycloak (client `e2e-tests`) and refreshed on its own.

The ports are the defaults (gateway 8080, Keycloak 8180). If you changed `PORT_GATEWAY` / `PORT_KEYCLOAK` in `infra/.env`, edit
`baseUrl` / `keycloakUrl` in the environment, or use `make bruno-run` below which reads `infra/.env`.

`frank` is suspended in the seed data: Keycloak refuses his login on purpose (an account-disabled test).

## What is in it

| Folder | What |
|---|---|
| `keycloak/` | The raw token answer (also stores the refresh token for `Refresh`/`Logout`), and a service-account token (client credentials) |
| `account/ media/ catalog/ notification/` | One folder per tag of the OpenAPI file, one request per operation, in contract order |
| `graphql/` | The operations of `contracts/graphql/examples` |
| `custom/` | Yours: the generator never touches it |

Every request has the contract text and the error codes in its **Docs** tab, an assertion on the success status, and tags:
`read`/`write` and the `x-access` value (`public`, `authenticated`, `owner`, `moderator`, `admin`, ...).

A few things that make the collection behave like a conversation instead of a list:

- **Writes never touch seed data.** `Register a user`, `Upload an image`, `Create a wallpaper` and `Create a collection` store what
  they created (`newUserId`, `uploadedAssetId`, `createdWallpaperId`, `createdCollectionId`) and the edit and delete requests
  work on those. If a create fails, the later requests fail with 404/422 instead of deleting something from the seed. (Favorites,
  notification read marks, preferences and moderation do change seed rows; `make reseed` puts them back.)
- **`If-Match`** is filled with the `ETag` of the latest response and left out when there was none, so the first write of a
  session is unconditional. A `409` after you hopped between resources means: send the `GET` of that resource first.
- **`Idempotency-Key`** is a fresh GUID per send.
- **Roles.** `List users`, `Send test notification`, `Delete a user` need `admin`; `Moderate a wallpaper` needs `mod` or `admin`.
  Run as another user and they answer 403 - that is the contract working, and a good thing to try.
- `Set avatar` / `Set banner` are skipped for users that have no seeded image of that kind.

Not in the collection: the SSE stream and the WebSocket (a request/response client cannot show a stream). Get a ticket with
`Create a stream ticket`, then:

```bash
curl -N "http://localhost:8080/api/v1/notifications/stream?ticket=<ticket>"     # or: -H "$(scripts/token.sh --header alice)"
```

## From the command line

```bash
make bruno-run                              # everything, as alice
make bruno-run U=admin                      # as another user
make bruno-run ARGS="--tags read"           # only reads, changes nothing
make bruno-run ARGS="catalog/wallpapers"    # one folder
make token U=mod ARGS=--decode              # just the token, decoded (roles, audience, expiry)
```

`make bruno-run` skips the `admin`/`moderator` requests when the user's token lacks that role, so `U=alice` is green on a correct
implementation. It starts the Bruno CLI through `npx` (Node 20+, version pinned in `scripts/bruno.sh`). Against `make up-mocks`
the answers are the examples from the contracts (the `graphql/` requests fail there: the mocks only know REST); against
`make up-apps` it is a smoke test of the real services. `make seed` first, for the ids.

## Keeping it in sync

The folders other than `custom/` are generated by `scripts/bruno-gen.py` from `contracts/openapi`, `contracts/graphql/examples` and
`seed/out/manifest.json`. After a contract change run `make bruno-gen` and commit the diff; CI runs `make bruno-check` and fails
when the committed collection differs. Do not edit generated files by hand: change the generator (the tables at the top of the
script decide which variable a path id uses, which body fields point at created things, which operations are skipped) or add your
own requests under `custom/`.

## Tokens without Bruno

```bash
scripts/token.sh                       # a token for alice (cached for its lifetime, in .token-cache/)
scripts/token.sh mod --decode          # header and claims, expiry
scripts/token.sh --client catalog-svc  # a service account, what one service sends to another
curl -H "$(scripts/token.sh --header bob)" http://localhost:8080/api/v1/users/me
```

`--list` shows the users and clients; `--json` the whole answer (refresh token included); `--no-cache` always asks Keycloak.
